# Наладчик — кабинет инженера

Офлайн-приложение для учёта доходов и командировок инженера-наладчика. Работает как обычная веб-страница, устанавливается как PWA и синхронизирует данные с приватным GitHub Gist.

## Возможности

- **Доходы**: аванс, окончательная зарплата, отпускные, премия, компенсация, прочие поступления.
- **Наличные и безналичные** поступления с указанием источника дохода и объекта.
- **Командировки**: направление, объект, даты начала и окончания, транспорт, цель поездки.
- **Количество суток рассчитывается автоматически** включительно по датам начала и окончания.
- **Суточные не входят в сумму доходов.** Это возмещение расходов: они показываются отдельно и справочно, но не увеличивают доход ни на одном экране и не попадают в CSV доходов.
- **Объекты**: площадки и заказчики с доходами, сутками и суточными по каждому объекту.
- **Отчёты**: доходы и командировки по месяцам, структура по типам, источникам, объектам и направлениям.
- **Фильтры, сортировка, поиск**, периоды «месяц / квартал / год / всё время».
- **Экспорт и импорт**: JSON-резервная копия, CSV доходов и командировок.
- **Тёмная и светлая темы**, адаптивная вёрстка, печать отчётов.
- **Офлайн-режим** через service worker.
- **Синхронизация с GitHub** через приватный Gist и Personal Access Token.

## Как хранятся данные

| Где | Что хранится |
| --- | --- |
| `localStorage` браузера | Рабочие данные, настройки, резервная копия |
| Приватный GitHub Gist | Копия данных для синхронизации между устройствами |
| Только в браузере | Personal Access Token |

Токен **не сохраняется** в Gist, не попадает в резервную копию и не должен попадать в репозиторий. Данные в Gist лежат в файле `naladchik-data.json`.

Ключи `localStorage`:

- `naladchik:data:v1` — данные приложения;
- `naladchik:backup:v1` — резервная копия перед импортом или загрузкой из Gist;
- `naladchik:github:v1` — токен, ID Gist и время синхронизации;
- `naladchik:ui:v1` — выбранный период и настройки интерфейса.

## Подключение GitHub

1. Создайте **classic** Personal Access Token с правом `gist` (или fine-grained token с доступом к Gists).
2. Откройте **Настройки → GitHub**.
3. Вставьте токен. ID Gist можно оставить пустым.
4. Нажмите **Создать Gist** — будет создан приватный Gist с файлом `naladchik-data.json`.
5. Для второго устройства вставьте тот же токен и ID Gist (или ссылку на Gist), затем нажмите **Загрузить**.

Доступны ручные действия «Отправить» и «Загрузить», а также автоматическая синхронизация при изменениях. При конфликте приложение предложит выбрать локальную или удалённую версию.

## Локальный запуск

Из папки проекта:

```powershell
python -m http.server 5173
```

Откройте `http://localhost:5173`.

Приложение не требует сборки: это статические HTML, CSS и JavaScript.

## Публикация на GitHub Pages

Сайт публикуется прямо из ветки `main`, без сборки:

1. Откройте **Settings → Pages**.
2. В разделе **Build and deployment** выберите **Deploy from a branch**.
3. Укажите ветку `main` и папку `/ (root)`, сохраните.
4. Сайт будет доступен по адресу `https://fzonov-png.github.io/naladchik/`.

Файл `.nojekyll` отключает обработку Jekyll и сохраняет служебные файлы.

## Приватность и безопасность

- Используйте отдельный токен только с правом `gist`.
- Не публикуйте токен и не добавляйте его в код или резервные копии.
- Gist должен быть **приватным**: приложение создаёт его именно таким.
- Данные хранятся в браузере и в вашем Gist; сторонние серверы не используются.
- Регулярно скачивайте JSON-резервную копию.
